What Was Done

Stage 3 & Stage 4 Implementation Pattern

  1. Added imports: datetime, JanuaryBracketFillStrategy
  2. Phase 1 in calculate_strategy():
    • Call _plan_january_bracket_fill_withdrawal()
    • Extract _jan_spending_withdrawal = plan.pnc_shortfall
    • Log decision to tax_strategy category
  3. Phase 2 in calculate_strategy():
    • Calculate available_for_conversion by subtracting _jan_spending_withdrawal
    • Call existing conversion method (BETR for Stage 3, IRMAA-aware for Stage 4)
    • Log decision with conversion amount and rate
  4. Apply spending withdrawal BEFORE rebalancing:
    • After DAF contribution applied to balances
    • Before _execute_rebalancing() call
    • Traditional→Cash transfer applied directly to balances_for_rebalance
  5. Added method: _plan_january_bracket_fill_withdrawal()
    • Reads config flag use_january_bracket_fill_strategy
    • Reads bracket data from income_rates.csv
    • Creates JanuaryBracketFillStrategy instance
    • Returns plan dict with pnc_shortfall and other fields

Notes

Why Stage 5, 6, 7 are More Complex:
• Stage 5 (SS): Social Security taxation creates a feedback loop (taxable SS depends on AGI, AGI depends on withdrawals)
• Stage 6 (RMD): Mandatory distributions add to ordinary income; must plan withdrawals around RMD requirements
• Stage 7 (Surviving Spouse): Single filing status changes bracket thresholds; conservative conversion strategy
